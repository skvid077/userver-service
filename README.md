# Исследование сборки userver-сервиса

Сервис создан командой `userver-create-service --grpc --mongo --postgresql build_study` в Docker-образе из задания. Проверяется замена GNU ld на LLVM LLD. В коде сервиса добавлена одна строка CMake; C++-файлы не изменены.

## Запуск

Нужен Docker с Linux-контейнерами на x86-64, минимум 4 доступных логических CPU и память для контейнера с лимитом 8 ГБ. Для подготовки инструментов нужен интернет.

Linux, из корня репозитория:

```bash
bash run.sh
```

Windows с Docker Desktop и WSL 2:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт использует заданный образ по digest и ограничения `--cpus=4 --cpuset-cpus=0-3 --memory=8g --memory-swap=8g`. Заново генерирует сервис, проверяет исходники и готовит Clang 18.1.8, LLD 18.1.8 и Clang Build Analyzer 1.6.0.

По умолчанию выполняются 10 пар с трассировкой, 6 пар без неё и по 2 прогрева на вариант в каждом режиме — 40 сборок. Результаты нового запуска записываются в `results/<идентификатор>/`. Контейнер и Linux-том сохраняются; имя контейнера — в `container.txt`.

## Что включено

- [report.pdf](report.pdf) — отчёт на двух страницах: окружение, методика, четыре вывода, гипотеза, ограничения и все измеряемые повторы.
- [all-results.csv](all-results.csv) — все 40 запусков сохранённой серии; `warmup=1` обозначает прогревы.
- [results/run/](results/run/) — сырой вывод анализатора `profile-*/analyzer.txt`, захваты, трассы, логи, метрики, команды сборки и архивы исходников.
- [results/diagnostics/](results/diagnostics/) — причина ошибки GNU ld с Zstandard и проверка повторного анализа захватов.
- `service/` — шаблон с изменением; [optimization.patch](optimization.patch) — патч из одной строки.
- `scripts/` — измерение и проверка данных, закреплённый архив анализатора и лицензии.

Прогревы исключены из измеряемых пар. Порядок AB/BA сбалансирован, кэш компиляции отключён. Перед каждой сборкой выполняется очистка. Подготовка и анализ находятся вне таймера. В обоих вариантах отключён автоматический выбор LLD и используется zlib-сжатие debug-информации; отличается только выбор линкера через патч.

## Проверка

```bash
python scripts/verify_results.py
```

Нужен Python 3.9 или новее. Команда сверяет CSV с сырыми трассами и Ninja, сравнивает исходники и команды, пересчитывает отдельные пары и диапазоны. Сами замеры можно независимо проверить новым запуском эксперимента.

Исходный сервис отмечен меткой `baseline`, вариант с LLD — `optimized`:

```bash
git diff baseline optimized -- service
```

Разница — одна строка в `service/CMakeLists.txt`. Замеры относятся к одному компьютеру и прогретому файловому кэшу. Интеграционные тесты с базами данных не запускались.
